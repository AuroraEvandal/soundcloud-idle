# Инструкция для фронтенда: от нуля до рабочей ссылки для Telegram

Цель: получить адрес сайта вида `https://название.vercel.app`, который открывается на телефоне и показывает игру. Игра пока работает на фейковых данных, подключение к настоящему серверу будет позже. Эту ссылку напарник вставит в бота, и вы сможете открыть игру внутри Telegram.

**Время:** 2-4 часа, если всё идёт гладко.

**Правило на весь процесс:** если в любом шаге что-то не получилось, не гадай. Скопируй текст ошибки целиком и покажи ИИ-агенту или напарнику.

## Шаг 0. Что должно быть установлено

| Что | Как проверить | Если нет |
|---|---|---|
| VS Code | Открывается | code.visualstudio.com |
| Git | В терминале VS Code `git --version` показывает версию | git-scm.com, жми Next на всех шагах |
| Node.js | В терминале `node -v` и `npm -v` показывают версии | см. шаг 1 |

Терминал в VS Code открывается через **Ctrl+`** (клавиша слева от единицы).

## Шаг 1. Установи Node.js

Node.js нужен, чтобы запускать и собирать проект.

1. Открой **nodejs.org**.
2. Скачай версию с пометкой **LTS** (она стабильная).
3. Установи, на всех шагах жми Next.
4. **Перезапусти VS Code** (иначе он не увидит Node).
5. В терминале выполни `node -v`. Должен показаться номер версии, например `v22.x.x`.

Если пишет «node не является внутренней или внешней командой», перезагрузи компьютер и проверь ещё раз.

## Шаг 2. Подтяни свежую версию проекта

1. Открой в VS Code папку репозитория (File → Open Folder).
2. Внизу слева посмотри название ветки. Тебе нужна ветка **`frontend`**. Если ты на `main` или другой, нажми на название ветки и выбери `frontend`. Если такой ветки нет, создай: Create new branch → `frontend`.
3. Подтяни чужие изменения: иконка **Source Control** (Ctrl+Shift+G) → кнопка **Sync Changes**. Или в терминале: `git pull`.
4. Если Git пишет про конфликт или просит что-то объединить, остановись и позови напарника, не нажимай наугад.

## Шаг 3. Прочитай правила проекта

В репозитории есть файлы, которые объясняют, как всё устроено:

- `AGENTS.md` (в корне): правила работы и структура.
- `docs/game-design.md`: правила игры.
- `docs/api.md`: **главный документ для тебя**. Там описано, какие запросы и ответы будут между игрой и сервером.

**Как запускать ИИ-агента.** Любое новое задание начинай с такой фразы:

> Прочитай AGENTS.md и docs/api.md и расскажи своими словами, что нужно сделать фронтенду. Пока ничего не меняй.

Если агент пересказывает неправильно, поправь его **до** того, как он начнёт писать код.

## Шаг 4. Убедись, что игра запускается

Проект фронтенда должен лежать в папке `frontend` и содержать файл `package.json`.

**Если игра уже лежит в `frontend`:**
1. В терминале: `cd frontend`
2. `npm install` (скачает библиотеки, займёт минуту; появится папка `node_modules`, она в `.gitignore`, это нормально).
3. `npm run dev`
4. В терминале появится адрес вроде `http://localhost:5173`. Открой его в браузере: игра должна работать.
5. Остановить сервер: **Ctrl+C** в терминале.

**Если игра лежит в другом месте:** скопируй её файлы в папку `frontend` так, чтобы там был `package.json`, и повтори.

**Если игры ещё нет в `frontend` и нужно начать с чистого листа:**
1. `cd frontend`
2. `npm create vite@latest . -- --template react`
3. Если спросит про непустую папку (там лежит README.md), выбери вариант **Ignore files and continue**.
4. `npm install`, затем `npm run dev`.

## Шаг 5. Вынеси данные и логику в один файл `src/api.js`

**Зачем.** Сейчас игра хранит всё в браузере. Это нормально для прототипа, но настоящие данные, оценки и очки должен считать сервер, иначе игроки смогут подделать результат. Чтобы потом подключить сервер без переписывания экранов, все обращения «к серверу» собирают в одном файле.

**Правило.** Экраны и компоненты **ничего не знают** о данных. Они только вызывают функции из `src/api.js` и показывают результат. На экранах остаётся только то, что относится к интерфейсу: какой экран открыт, какие карточки выбраны сейчас, анимации.

**Задача для ИИ-агента:**

> Вынеси всю игровую логику и данные (карточки, оценки, ответы ботов, профиль, опыт) из компонентов в файл src/api.js. Создай там функции login, getProfile, getHand, startBattle, submitRound. Каждая функция должна возвращать объект в точно таком формате, как описано в docs/api.md. Компоненты должны получать данные только через вызовы этих функций. Игровую логику, которая сейчас лежит в компонентах, перенеси внутрь этих функций.

**Каркас файла** (агент напишет его за тебя, но тебе полезно понимать, как он устроен):

```js
import { supabase } from './supabase'

// true = фейковые данные, false = настоящий сервер.
// Переключаем по одной функции, когда бэкенд готов.
const MOCK = {
  login: true,
  getProfile: true,
  getHand: true,
  startBattle: true,
  submitRound: true,
}

// Общий вызов серверной функции
async function call(name, body) {
  const initData = window.Telegram?.WebApp?.initData || ''
  const { data, error } = await supabase.functions.invoke(name, {
    body: { initData, ...body },
  })
  if (error) throw error
  if (data?.error) throw new Error(data.error.code)
  return data
}

const wait = (ms) => new Promise((r) => setTimeout(r, ms))

export async function login() {
  if (MOCK.login || !supabase) {
    await wait(300)
    return { is_new: false, player: { /* пример из docs/api.md */ } }
  }
  return call('login', {})
}

export async function submitRound(battleId, roundNumber, cardIds) {
  if (MOCK.submitRound || !supabase) {
    await wait(500)
    return { /* пример ответа из docs/api.md */ }
  }
  return call('submit-round', { battleId, roundNumber, cardIds })
}
```

Остальные функции делаются по тому же образцу.

**Что важно в фейковых ответах:**
- Структура и названия полей **точь-в-точь как в `docs/api.md`** (`scores`, `rhyme`, `next_round`, `rewards` и т.д.). Если назвать иначе, при подключении сервера всё сломается.
- Фейк должен вести себя как настоящий: после 2 выигранных раундов `next_round` равен `null`, а `rewards` заполнен.
- Если фронту нужно поле, которого нет в `api.md`, **не добавляй его молча**. Сначала напиши напарнику, поправьте `docs/api.md`, и только потом код.

**Как проверить, что всё вынесено:**
1. Нажми **Ctrl+Shift+F** (поиск по проекту) и найди слово `supabase`. Оно должно встречаться только в `src/api.js` и `src/supabase.js`, но не в компонентах.
2. Пройди игру целиком: профиль, начало баттла, три раунда, награда. Всё должно работать, как раньше.

## Шаг 6. Подключи Telegram

1. Открой `index.html` (в папке `frontend`) и добавь в блок `<head>`:
   ```html
   <script src="https://telegram.org/js/telegram-web-app.js"></script>
   ```
2. В главном файле (обычно `src/main.jsx`), до запуска React, добавь:
   ```js
   const tg = window.Telegram?.WebApp
   if (tg) {
     tg.ready()
     tg.expand()
   }
   ```
   `ready()` сообщает Telegram, что приложение загрузилось, `expand()` раскрывает его на весь экран.
3. **Приложение должно работать и вне Telegram** (в обычном браузере): там `window.Telegram.WebApp.initData` пустая, и это нормально. Нигде не должно быть кода, который падает без Telegram. В `api.js` выше это уже учтено: `initData` берётся с запасным значением `''`.

## Шаг 7. Подготовь подключение к Supabase

Пока сервера нет, этот шаг ничего не меняет в игре. Но подготовить место нужно сейчас.

1. В терминале в папке `frontend`: `npm install @supabase/supabase-js`
2. Создай файл `src/supabase.js`:
   ```js
   import { createClient } from '@supabase/supabase-js'

   const url = import.meta.env.VITE_SUPABASE_URL
   const key = import.meta.env.VITE_SUPABASE_ANON_KEY

   // Если ключей нет, клиент не создаётся и игра работает на фейках
   export const supabase = url && key ? createClient(url, key) : null
   ```
   Проверка `url && key` нужна, чтобы без ключей игра не падала белым экраном.
3. Создай файл `frontend/.env.example`:
   ```
   VITE_SUPABASE_URL=
   VITE_SUPABASE_ANON_KEY=
   ```
   Этот файл можно коммитить: он показывает, какие значения нужны, но сами значения пустые.
4. Когда напарник пришлёт настоящие значения (**Project URL** и ключ **anon**), создай файл `frontend/.env` по образцу и впиши их. Файл `.env` **нельзя коммитить**: он уже в `.gitignore`, но проверь. После `git add` в списке изменений `.env` быть не должен.

**Ключи.** Во фронтенде допустим только ключ `anon`. Ключ `service_role` и токен Telegram-бота **нельзя** класть во фронтенд ни при каких условиях.

## Шаг 8. Проверь на телефонном экране и собери проект

1. В `index.html` должна быть строка (в шаблоне Vite она есть по умолчанию):
   ```html
   <meta name="viewport" content="width=device-width, initial-scale=1.0" />
   ```
2. Запусти `npm run dev`, открой игру в Chrome, нажми **F12**, потом **Ctrl+Shift+M** (режим устройства) и выбери телефон. Проверь:
   - ничего не вылезает за экран и нет горизонтальной прокрутки;
   - кнопки достаточно большие, чтобы попасть пальцем;
   - текст читается.
3. Проверь сборку: `npm run build`. Если она закончилась ошибкой, на хостинге она тоже упадёт, поэтому исправь ошибку сейчас. Появится папка `dist` (её тоже можно добавить в `.gitignore`).

## Шаг 10. Слей работу в ветку `main`

Хостинг (Vercel) публикует основной адрес сайта из ветки `main`. Поэтому код должен попасть туда.

1. Открой репозиторий на github.com.
2. Нажми жёлтую плашку **Compare & pull request** (или вкладка Pull requests → New pull request).
3. Слева выбери `main`, справа `frontend`.
4. Нажми **Create pull request**, затем **Merge pull request**, затем **Confirm merge**.
5. Перейди на `main` в VS Code и сделай pull, чтобы ветки были синхронны.

## Шаг 11. Выложи сайт на Vercel

1. Открой **vercel.com**, нажми **Sign Up** → **Continue with GitHub** и разреши доступ.
2. **Add New...** → **Project**.
3. Найди в списке репозиторий проекта и нажми **Import**. Если репозитория в списке нет, нажми **Adjust GitHub App Permissions** и выдай Vercel доступ к нему.
4. На экране настроек:
   - **Framework Preset:** должен определиться сам как **Vite**.
   - **Root Directory:** нажми **Edit** и выбери папку **`frontend`**. Это важно: без этого Vercel не найдёт проект.
   - Build Command (`npm run build`) и Output Directory (`dist`) оставь как есть.
5. Нажми **Deploy** и подожди 1-2 минуты.
6. Получишь адрес вроде `https://название.vercel.app`. Открой его **на компьютере и на телефоне** (в обычном браузере). Игра должна работать так же, как локально.

Дальше каждый раз, когда код попадает в `main`, Vercel сам обновляет сайт.

**Про ключи на Vercel.** Когда подключите настоящий сервер, значения `VITE_SUPABASE_URL` и `VITE_SUPABASE_ANON_KEY` нужно добавить в Vercel: Project → Settings → Environment Variables. После добавления нужно сделать **Redeploy** (Deployments → три точки у последнего деплоя → Redeploy), иначе они не подхватятся.

**Про тариф.** Насколько мы знаем, бесплатный тариф Vercel предназначен для некоммерческого использования. Для тестов он подходит. Перед монетизацией проверьте актуальные условия или перенесите сайт на другой хостинг (Netlify, Cloudflare Pages).

## Шаг 12. Отправь результат напарнику

Напиши напарнику:
- адрес сайта (HTTPS);
- что именно проверил (открывается на ПК, на телефоне, баттл проходит до конца);
- что не работает или вызывает сомнения.

Дальше напарник вставит адрес в BotFather (Bot Settings → Menu Button), и вы вместе проверите игру внутри Telegram.

---

## Что нужно от напарника (бэкенд)

- **Project URL** и ключ **anon** из Supabase (Settings → API). Эти значения публичные, их можно отправлять в личные сообщения.
- Сообщение «функция `login` готова»: тогда в `api.js` меняешь `MOCK.login` на `false`. Следующие функции подключаются по одной, так, как будет готов бэкенд.

## Частые проблемы

| Проблема | Что делать |
|---|---|
| `npm` или `node` не найдены | Перезапусти VS Code или компьютер. Если не помогло, переустанови Node.js |
| Белый экран | Открой консоль браузера (F12 → вкладка Console), скопируй красную ошибку и покажи агенту |
| Сборка на Vercel упала, а локально работает | Откройте лог деплоя (Deployments → нужный деплой → Build Logs). Частая причина: регистр букв в именах файлов. `App.jsx` и `app.jsx` на Windows одно и то же, а на сервере разные файлы |
| На Vercel 404 или пустая страница | Проверь, что **Root Directory** равен `frontend` |
| Страница открывается, но после обновления на внутреннем пути 404 | Это бывает, если используется роутер (React Router). Добавь файл `frontend/vercel.json`: `{ "rewrites": [{ "source": "/(.*)", "destination": "/index.html" }] }` |
| Картинки не загружаются | Проверь пути: файлы из папки `public` подключаются как `/имя.png`, без `public/` |
| Telegram не открывает сайт | Адрес должен быть HTTPS и публичным (не `localhost`). Открой его в обычном браузере телефона и убедись, что он работает |
| В списке изменений Git видно `.env` | Не коммить. Проверь, что в корневом `.gitignore` есть строка `.env`. Если ключ уже ушёл на GitHub, считай его скомпрометированным и сообщи напарнику, чтобы его перевыпустили |
