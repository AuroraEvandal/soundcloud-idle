# API: фронт <-> серверные функции (MVP, v0.1)

Это договор между бэкендом и фронтом. Если нужно что-то изменить, сначала правим этот файл и сообщаем друг другу, потом код.

## Общие правила

- Все функции вызываются через Supabase:
  ```js
  const { data, error } = await supabase.functions.invoke('имя-функции', { body: { ... } })
  ```
- В **каждый** запрос фронт добавляет поле `initData`: `window.Telegram.WebApp.initData`. По нему сервер проверяет, что это настоящий игрок.
- Фронт присылает **только ID** (карточек, батла, соперника). Тексты, оценки и очки всегда считает сервер.
- Все ответы в формате JSON.

### Формат ошибки

Если что-то пошло не так, функция возвращает:

```json
{ "error": { "code": "CARD_NOT_OWNED", "message": "У игрока нет карточки 142" } }
```

| Код | Когда |
|---|---|
| `INVALID_INIT_DATA` | Подпись Telegram не прошла проверку |
| `PLAYER_NOT_FOUND` | Игрока нет в базе (нужно сначала вызвать `login`) |
| `BATTLE_NOT_FOUND` | Нет такого батла или он чужой |
| `BATTLE_FINISHED` | Батл уже закончен |
| `ROUND_ALREADY_SUBMITTED` | Этот раунд уже отправлен |
| `INVALID_ROUND` | Номер раунда не тот, который сейчас активен |
| `INVALID_CARDS` | Не 4 карточки или слоты в неправильном порядке |
| `CARD_NOT_OWNED` | У игрока нет такой карточки |
| `CARD_BURNED` | Карточка сгорела: лимит боёв (3) исчерпан |
| `OPPONENT_LOCKED` | Соперник ещё не открыт (мало популярности) |
| `IDEMPOTENCY_CONFLICT` | `requestId` уже использован с другим содержимым запроса |
| `BATTLE_IN_PROGRESS` | У игрока уже есть активный батл с другим соперником |
| `CARD_POOL_TOO_SMALL` | Для одного из слотов у игрока меньше 4 доступных карточек |
| `INTERNAL` | Ошибка сервера, можно повторить |

## 1. `login`

Вызывается при каждом открытии приложения. Находит игрока или создаёт нового.

**Запрос**
```json
{ "initData": "..." }
```

**Ответ**
```json
{
  "is_new": false,
  "player": {
    "id": "b1c2d3e4-...",
    "username": "vasya",
    "avatar": "default",
    "level": 3,
    "xp": 240,
    "xp_to_next": 400,
    "popularity": 120,
    "coins": 350,
    "skills": { "rhyme": 3, "flow": 2, "punch": 4, "charisma": 1 }
  }
}
```

`login` создаёт игрока один раз и выдаёт стартовые карточки. Повторный вызов не сбрасывает прогресс.

`username` берётся из Telegram (`username`, иначе `first_name`, иначе `player`) и **обновляется при каждом входе**, если игрок сменил его в Telegram. Отдельно приложение имя не запрашивает.

## 3. `get-hand`

Карточки игрока для сборки строчки.

> Рука создаётся **сервером**: для каждого слота выбирается ровно 4 случайные карточки из тех, что есть у игрока. Рука запоминается в батле, поэтому `submit-round` принимает только карточки из неё. Эта же рука приходит в ответах `start-battle` и `submit-round`, а `get-hand` нужен, чтобы восстановить экран, если игрок перезапустил приложение посреди раунда.
>
> Правила руки:
> - Выдаются только «рабочие» карточки: поле `uses_left` (осталось боёв до сгорания) больше 0.
> - В раундах 2 и 3 карточки, уже прошедшие в этом баттле, стараются не выдаваться снова; если на слот набирается меньше 4, недостающие добираются из остальных рабочих карточек (могут повториться с ранними раундами).
> - Если между раундами часть карточек сгорела, рука в слоте может быть короче 4.
> - У каждой карточки в ответе есть поле `uses_left`.

**Запрос**
```json
{ "initData": "...", "battleId": "9f8e7d6c-..." }
```

**Ответ**
```json
{
  "battle": {
    "id": "9f8e7d6c-...",
    "status": "active",
    "opponent": { "id": 1, "name": "МС Подвал", "style": "Дворовый, грубоватый", "level": 1 },
    "player_rounds_won": 0,
    "opponent_rounds_won": 0
  },
  "round": { "number": 1, "theme": "деньги" },
  "last_result": null,
  "cards": {
    "setup": [
      { "id": 140, "text": "Ты в бою как нищий — пустой кошелёк", "theme": "деньги", "rarity": "common", "syllables": 11, "uses_left": 3 }
    ],
    "development": [
      { "id": 141, "text": "А я на сцене — ты просто игрок", "theme": "деньги", "rarity": "common", "syllables": 10, "uses_left": 2 }
    ],
    "boost": [
      { "id": 143, "text": "Ты копишь на кроссы, я кручу бабки", "theme": "деньги", "rarity": "common", "syllables": 11, "uses_left": 3 }
    ],
    "punch": [
      { "id": 142, "text": "Твой флоу, бро, — домашние тапки", "theme": "ирония", "rarity": "rare", "syllables": 10, "uses_left": 1, "bonus": { "type": "flat_points", "value": 3 } }
    ]
  }
}
```

Также возвращаются `round` (текущий раунд и тема), `battle` (соперник и счёт) и `last_result` (последний отправленный раунд, если он есть; `null`, если ещё нет). Если игрок закрыл приложение после отправки раунда, фронт показывает сохранённый результат и позволяет продолжить. После завершения батла `round` и `cards` равны `null`, а `last_result` содержит финальный результат.

Слоты: `setup` (завязка), `development` (развитие), `boost` (усиление), `punch` (панч).

## 4. `start-battle`

Создаёт батл. Сервер сам выбирает темы для 3 раундов, а фронту отдаёт тему первого.

**Запрос**
```json
{ "initData": "...", "opponentId": 1, "requestId": "UUID" }
```

`requestId` генерируется фронтом один раз на попытку начать батл и повторяется при сетевом повторе. Повтор с тем же ID возвращает тот же батл, а не создаёт второй.

**Ответ**
```json
{
  "battle": {
    "id": "9f8e7d6c-...",
    "status": "active",
    "opponent": { "id": 1, "name": "МС Подвал", "style": "Дворовый, грубоватый", "level": 1 },
    "player_rounds_won": 0,
    "opponent_rounds_won": 0
  },
  "round": { "number": 1, "theme": "деньги" },
  "hand": { "setup": [], "development": [], "boost": [], "punch": [] }
}
```

Одновременно у игрока может быть только один активный батл. Повторный старт с тем же соперником вернёт его состояние; запрос с другим соперником получит `BATTLE_IN_PROGRESS`.

Ошибки: `OPPONENT_LOCKED`, `BATTLE_IN_PROGRESS`, `CARD_POOL_TOO_SMALL`.

## 5. `submit-round`

Главная функция. Принимает собранную строчку, оценивает, возвращает результат.

**Запрос**

`cardIds` строго в порядке слотов: завязка, развитие, усиление, панч.
```json
{
  "initData": "...",
  "battleId": "9f8e7d6c-...",
  "roundNumber": 1,
  "requestId": "UUID",
  "cardIds": [140, 141, 143, 142]
}
```

`requestId` генерируется фронтом один раз для отправляемой строки и сохраняется при сетевых повторах. Повтор того же запроса возвращает сохранённый ответ без повторной оценки и наград. Повторный номер раунда с другим содержимым возвращает `ROUND_ALREADY_SUBMITTED`.

**Ответ (батл продолжается)**
```json
{
  "round": {
    "number": 1,
    "theme": "деньги",
    "player": {
      "lines": [
        "Ты в бою как нищий — пустой кошелёк",
        "А я на сцене — ты просто игрок",
        "Ты копишь на кроссы, я кручу бабки",
        "Твой флоу, бро, — домашние тапки"
      ],
      "scores": { "rhyme": 8.5, "flow": 9, "punch": 7, "meaning": 6 },
      "points": 80,
      "comment": "Панч про домашние тапки смешной и в тему, но первая пара строк слабо связана со второй."
    },
    "opponent": {
      "lines": [
        "Деньги — пыль, я вырос на районе",
        "А ты рос в тепле и на балконе",
        "Я голодным лез на каждый сход",
        "А ты ждал, что мамка принесёт"
      ],
      "scores": { "rhyme": 9, "flow": 8, "punch": 6, "meaning": 7 },
      "points": 75
    },
    "winner": "player"
  },
  "battle": {
    "status": "active",
    "player_rounds_won": 1,
    "opponent_rounds_won": 0
  },
  "next_round": { "number": 2, "theme": "улица" },
  "hand": { "setup": [], "development": [], "boost": [], "punch": [] },
  "rewards": null
}
```

**Ответ (батл закончен)**

Батл заканчивается, когда кто-то выиграл 2 раунда. Тогда `next_round` равен `null`, а `rewards` заполнен:
```json
{
  "battle": { "status": "finished", "result": "win", "player_rounds_won": 2, "opponent_rounds_won": 1 },
  "next_round": null,
  "hand": null,
  "rewards": { "xp_change": 25, "popularity_change": 15, "level_up": false, "new_level": 3 }
}
```

Ошибки: `BATTLE_NOT_FOUND`, `BATTLE_FINISHED`, `ROUND_ALREADY_SUBMITTED`, `INVALID_ROUND`, `INVALID_CARDS`, `CARD_NOT_OWNED`, `CARD_BURNED`, `IDEMPOTENCY_CONFLICT`.

## Как формируются очки раунда (для справки)

```
итог = (рифма × 0,25 + флоу × 0,25 + панч × 0,30 + смысл × 0,20) × 10 + бонусы карточек
```

ИИ-судьи в MVP нет — все критерии считает код на сервере:

- **рифма** и **флоу** — алгоритмы;
- **панч** — из свойств карточки в слоте «панч»: базово по редкости (common 5, rare 7, epic 9), +0,5 за каждый пункт бонуса, максимум 10;
- **смысл** — из таблицы связей тем `theme_relations`: средняя сила связи тем карточек между собой (6 пар) и каждой карточки с темой раунда. Одинаковые темы дают 10, пары без записи — нейтральные 5. Таблицу заполняет автор игры.
- **комментарий** («comment») собирается из шаблонов по сильной и слабой стороне строчки.

Количество оценок в день не ограничено. Фронту знать формулу не нужно.

## Для фронта: как работать, пока бэкенд не готов

Сделай файл `frontend/src/api.js`, где каждая функция из этого документа возвращает **фейковый ответ** в таком же формате:

```js
export async function submitRound(battleId, roundNumber, cardIds) {
  // TODO: заменить на supabase.functions.invoke('submit-round', ...)
  return { /* пример ответа из этого документа */ }
}
```

Когда бэкенд будет готов, меняется только содержимое этого файла, а экраны остаются как есть.

## Принятые решения

- **ИИ-судьи в MVP нет.** Все четыре критерия (рифма, флоу, панч, смысл) считает код на сервере; панч — из свойств карточки-панча, смысл — из таблицы связей тем `theme_relations`. Дневной лимит оценок отменён.
- **Поле `ai_requests_left` устарело и удалено из ответов.** Фронт должен перестать показывать счётчик «оценок осталось». (Код ИИ-судьи сохранён в `supabase/functions/_shared/scoring.ts` выключенным — на случай возврата ИИ после MVP.)
- **Рука:** ровно 4 карточки на каждый слот, выбираются случайно из карточек игрока. Карточка не может оказаться в двух слотах (каждая карточка создана под свой слот).
- **Лимит карточки:** 3 боя. Каждый батл, в котором карточка прошла хотя бы в одном раунде, списывает с неё одно использование. Когда использования кончаются, карточка «сгорает»: остаётся в колоде игрока (видна как сгоревшая), но больше не выдаётся в руку. Восстановления пока нет — новые карточки добавляются контентом (стартовый набор / будущие паки).
- **Нехватка карточек:** если при старте баттла на какой-то слот меньше 4 рабочих карточек — `CARD_POOL_TOO_SMALL`. В середине баттла рука может быть короче 4, но не меньше 1 (софт-лок внутри баттла исключён).
- **Опыт для следующего уровня:** `round(100 × 1.1^(level − 1))`. Уровень 1 → 100, уровень 2 → 110, уровень 3 → 121, уровень 4 → 133 и т.д.
- **Хранение опыта:** поле `xp` в `players` это опыт **внутри текущего уровня**. При повышении лишний опыт переносится на следующий уровень.
- **Победа в батле:** +25 опыта.
- **Поражение в батле:** −10…15 опыта (случайно). Опыт не уходит ниже 0, уровень не понижается.
- **Бонус к опыту** можно будет прокачивать позже (не в MVP).
- **Покупка карточек:** не в MVP, функция не нужна.

- **Два отдельных числа:** опыт (`xp`) даёт уровни, популярность (`popularity`) открывает локации и соперников.
- **Популярность (черновик, можно менять):** победа +15, поражение −5…10. Ниже порога уже открытой локации не падает, чтобы локации не закрывались обратно.
