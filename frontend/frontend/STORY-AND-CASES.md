# Фрешмен: вступление и кейсы

Вступление пересобрано: светлая страница-комикс, отдельный тёмный кадр,
текст под кадром, закреплённая навигация. `StoryIntro.module.css` изолирует
стили; тип сцены задаётся через `data-scene`, рамка камеры — отдельным классом.
Это устраняет прежний конфликт `story-camera`, который делал третью сцену
абсолютной и накладывал её на заголовок. Центральная область прокручивается
на коротких экранах, весь текст остаётся в обычном потоке.

## Решение для текущей версии

Анимированный комикс внутри React, выбран пользователем вместо отдельного видео.
Пять сцен по 5 секунд, последняя ждёт действия игрока. Пауза, назад, далее,
пропуск и повтор из профиля. При reduced motion сцены переключаются вручную.
Автопоказ — новым игрокам по `login.is_new`; незавершённый просмотр повторится
с начала при следующем входе. Локальная отметка привязана к ID игрока,
это настройка интерфейса, а не игровой прогресс.

1. **Новый голос.** Фрешмен приходит в индустрию с треками и большими планами.
2. **Ноль ответов.** Он диссит сцену, но его никто не знает и не слушает.
3. **Камера включена.** Создаёт TikTok, выкладывает сниппеты и разносит рэперов.
4. **Ты в рекомендациях.** Комментарии спорят, видео разлетается, имя замечают.
5. **Первый вызов.** 3гот2010: «В интернете ты громкий. Во дворе повторишь?»
   Переход в существующий экран баттлов; серверный ID соперника остаётся 1.

Числа просмотров и комментарии в комиксе — художественная часть истории,
не начисление популярности. Реплики относятся к вымышленным персонажам игры.
Иллюстрация главного героя выделена из `playericon.jpg` встроенным imagegen;
исходный JPEG сохранён. Одежда использует существующие PNG-слои.

## Приложение «Казик»

Тёмная витрина, два пиксельных кейса, цена в Telegram Stars, состав и лента
предпросмотра открытия. Никаких платежей и выдачи предметов в этой версии.
Демо показывает выбранный пользователем предмет: это проверка анимации,
не розыгрыш и не имитация фактической вероятности выигрыша.

### UNDERGROUND — 29 Stars

Предложение для будущего серверного каталога: ровно один легендарный предмет.
Категории: строчка 60%, одежда 25%, оборудование 15%. Внутри категории
вероятности конкретных предметов должны быть опубликованы до покупки.
В предпросмотре по одному концепту каждой категории. Шансы фиксированы,
не меняются от истории покупок, баланса или поведения игрока.

Дубликаты: предложенная компенсация — фрагменты той же категории;
10 дубликатов можно обменять на выбранный предмет категории. Это отдельная
серверная механика, пока не реализована. Предметы и фрагменты нельзя
обменивать обратно на Stars; обещать денежную окупаемость нельзя.

### GIFT VAULT — 100 Stars

Будущие коллекционные Telegram-подарки. Сейчас показаны только концепты:
«Неоновый талисман», «Хрустальное сердце», «Корона сцены». Это не реальные
Telegram NFT, не подтверждённый запас и не обещание выдачи.

Шансы не назначены до появления реального каталога, стоимости закупки,
проверенной передачи и резерва подарков. Целевая маржа должна получаться из
публичных фиксированных вероятностей, а не персональной подкрутки.
Ожидаемая себестоимость открытия = сумма(вероятность × стоимость выдачи);
маржа = цена − ожидаемая себестоимость − расходы. Без этих данных «окупаемость»
в процентах была бы выдумкой. Не добавлять автопокупку, фальшивые выигрыши
других игроков, искусственные «почти выпало» и предложения отыграться.

## До настоящего запуска

Это фронтенд-основа, существующий API не меняется. Отдельным этапом сначала
согласовать `docs/api.md`, затем реализовать серверные каталоги и выдачу.
Текущая БД принимает только common/rare/epic: legendary требует миграции,
пересмотра серверной оценки панча и баланса, а не только нового цвета.
Флаги существующего API оставлены как в текущем checkout: `MOCK` = false;
при отсутствии переменных Supabase уже существующий код использует моки.
В мок-режиме ID игрока меняется при перезагрузке страницы: отметка вступления
тоже начинается заново. Для настоящего аккаунта ключ привязан к стабильному ID.

Оплата цифровых товаров: Stars (`XTR`), серверное подтверждение
`successful_payment`, уникальный `telegram_payment_charge_id`, идемпотентная
выдача и журнал заказов. Закрытие invoice на клиенте не доказывает оплату.
Нужны восстановление после сбоя, возвраты, `/paysupport`, резерв конкретного
подарка и подтверждение доставки. Проверить возрастные/региональные ограничения
для платных случайных наград до включения продаж.

Официальные источники, проверены 2026-11-02:
- https://core.telegram.org/bots/payments-stars
- https://telegram.org/tos/bot-developers

## Идеи следующего сюжетного шага

- После каждого соперника — короткая глава и реакция сцены в существующем ТГ.
- Сюжетные задания «запиши первый сниппет» и «собери первый панч» с серверным
  учётом выполнения, без второй параллельной системы прогресса.
- Вымышленная лента TikTok: клипы игрока, ответы соперников, тизер следующего
  баттла. Пока существует только как сцена вступления.

## Проверка

Новый игрок → вступление → пауза/вперёд/пропуск → SoundWave → 3гот2010.
Профиль → повтор вступления. Главный экран → Казик → оба кейса → выбранный
предмет → бесплатная анимация. Монеты и инвентарь должны остаться прежними.
Проверить ареною, гардеробом, профилем и афишами новую модель и слои одежды.

Автопроверки: `npm run build`, `node --test tests/story-cases.test.mjs`.
Дополнительно пройден локальный рендер React без браузера: вступление,
витрина с отключённой покупкой и персонаж со слоем одежды. У трёх новых PNG
проверены размеры и прозрачность. Это не проверка визуальной компоновки.
Визуальная проверка в браузере не выполнена: инструмент отклонил разрешение
на открытие локального адреса. Подгонку слоёв одежды и размеры на телефоне
нужно подтвердить вручную.
