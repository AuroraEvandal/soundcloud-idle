# Backend: Supabase

В `backend/schema.sql` находится исходная схема проекта, а готовые карточки для старта — в `backend/seed.sql`.
Edge Functions размещены в `supabase/functions/`, настройки их проверки — в `supabase/config.toml`, изменения схемы для уже созданной базы — в `supabase/migrations/`.

## Настройка проекта

1. В Supabase создай проект и выполни `backend/schema.sql` в SQL Editor.
2. Выполни `backend/seed.sql`, чтобы добавить карточки, темы, стартовую колоду и каталог одежды.
3. Установи Supabase CLI, выполни `supabase link --project-ref <ID_ПРОЕКТА>`, затем `supabase db push`.
4. Добавь секрет `TELEGRAM_BOT_TOKEN` в Supabase Secrets. Ключи OpenAI для MVP не нужны — ИИ-судьи нет, оценки считает код.
5. Разверни функции командой `supabase functions deploy` (если Docker не установлен, используй `supabase functions deploy --use-api`).
6. Добавь во фронтенд `.env` адрес проекта и только публичный `anon`-ключ:

   ```env
   VITE_SUPABASE_URL=https://<ID_ПРОЕКТА>.supabase.co
   VITE_SUPABASE_ANON_KEY=<ПУБЛИЧНЫЙ_ANON_КЛЮЧ>
   ```

Ключ `service_role` не добавляй во фронтенд. Edge Functions используют серверный секрет Supabase и проверяют подпись Telegram `initData`.

## Что реализовано

- Баттлы: `login`, `get-profile`, `get-hand`, `start-battle`, `submit-round`.
- Студия: `get-studio`, `record-snippet`, `select-beat`.
- Магазин и гардероб: `get-shop`, `buy-item`, `get-wardrobe`, `equip-item`, `buy-beat`.
- Пак и колода: `open-pack`, `get-deck`.
- Старт батла и выдача руки выполняются транзакционно в Postgres. У игрока может быть только один активный батл.
- `submit-round` атомарно записывает результат, меняет счёт и выдаёт награды. Повтор того же `requestId` возвращает сохранённый JSON без повторной награды.
- `get-hand` возвращает текущий раунд, руку, счёт и последний результат, поэтому фронт может восстановить батл после перезапуска.
- Все четыре критерия считаются кодом на сервере, ИИ-судьи в MVP нет: рифма и флоу — алгоритмы, панч — из редкости и бонуса карточки-панча, смысл — из таблицы связей тем `theme_relations` (заполняет автор игры; пока таблица пустая, смысл выходит нейтральным). Код вызова OpenAI сохранён в `_shared/scoring.ts` выключенным. Лимит оценок в день отменён.

Контракт всех перечисленных функций описан в `docs/api.md`. Фронтенд может переключать экономические экраны с моков на сервер по одному, когда готова интеграция соответствующего экрана.

## Одежда (косметика)

Таблицы готовы и совпадают с наброском из `API-PROPOSAL.md`:

- `clothing` — каталог вещей (слот, редкость, цена, картинки, бонус);
- `player_clothing` — купленные вещи;
- `player_outfit` — надетые вещи, один ряд на слот (`hat`, `hoodie`, `pants`, `shoe`, `chain`).

Каталог заполняется из `backend/seed.sql` (9 вещей, те же id, что в мок-каталоге фронта). Для уже созданной базы таблицы добавляет `supabase/migrations/20261025_clothing.sql`. Функции магазина и гардероба реализованы и описаны в `docs/api.md`.

## Экономика v0.2

Для существующего проекта миграция `supabase/migrations/20261026120000_economy.sql` добавляет таблицы и атомарные RPC покупки. Каталог битов, оборудования и паков, как и каталог карточек/одежды, заполняется через `backend/seed.sql`; сид можно запускать повторно. Новые проекты создают таблицы экономики из `backend/schema.sql`.
