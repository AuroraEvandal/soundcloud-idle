# Как менять баланс MVP

В Supabase открой Table Editor → `game_balance`: там одна строка `id=true`.
Таблица доступна администратору; игроки не могут читать или менять её напрямую.
Сохрани новые числа — сервер использует их в новых раундах и открытиях паков.
Переиздавать фронтенд и Edge Functions не нужно. Уже сохранённые результаты не меняются.

| Поле | Сейчас | Что означает |
| --- | --- | --- |
| `skill_step` | 0.02 | +2% к вкладу рифмы/флоу/панча за каждый пункт соответствующего навыка выше 1 |
| `charisma_step` | 0.01 | +1% к сумме критериев за пункт харизмы выше 1 и за бонус харизмы надетой одежды |
| `max_skill_bonus` | 0.5 | Не больше +50% для каждого множителя |
| `common_weight` | 70 | Вес обычной карточки |
| `rare_weight` | 24 | Вес редкой карточки |
| `epic_weight` | 6 | Вес эпической карточки |

Например, `skill_step=0.01` уменьшает рост вклада навыка с 2% до 1% за пункт.
При нулевых `skill_step` и `charisma_step` навыки временно не влияют на очки.
Веса редкости относительные: 70/24/6 дают 70%/24%/6%, если в каталоге есть все
три категории. После выбора редкости сначала выбирается новая карточка этой
редкости; когда таких нет, выпадает дубликат. Ролл одежды (7%) выполняется раньше.

Для SQL Editor тот же пример:

```sql
update public.game_balance
set skill_step = 0.01, charisma_step = 0.01,
    max_skill_bonus = 0.5,
    common_weight = 70, rare_weight = 24, epic_weight = 6
where id = true;
```

Цены битов/оборудования/паков находятся в `beats`, `equipment`, `packs`.
Награды баттлов, лимит карточек, порог хайпа и восстановление энергии пока
задаются SQL-функциями. Их общий темп в этом обновлении не менялся:
для него нужен плейтест, особенно расход до 8–12 разных карточек за батл.
