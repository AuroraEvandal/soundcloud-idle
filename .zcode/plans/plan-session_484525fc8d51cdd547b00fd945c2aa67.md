План: ник из Telegram + рука по 4 карты на слот + лимит карт «3 боя»

Согласованные решения
- Ник: из Telegram (username → first_name → 'player'), синхронизируется при каждом входе. Экран ввода ника удаляется.
- Рука: ровно 4 карты на каждый слот (16 всего), карты остаются привязаны к слотам — одна карта не может оказаться в двух слотах.
- Лимит карт: у каждой карты игрока 3 боя; использовал в бою — минус один. На 0 карта «сгорает»: остаётся в колоде видимой (серой, «сгорела»), но больше не выдаётся. На карточке — бейдж с остатком (в руке и в колоде).
- Исчерпание: ничего не восстанавливаем. Если при старте нового баттла на слот меньше 4 рабочих карт — ошибка CARD_POOL_TOO_SMALL (новые карты добавишь в БД сам).
- Анти-спам между раундами: при раздаче 2-го/3-го раунда карта, уже использованная в этом баттле, не выдаётся, если без неё остаётся ≥4 вариантов; иначе — обычный пул. Один бой списывает с карты не больше 1 использования (даже если она прошла в нескольких раундах).

Шаг 1. Документация (по правилам — сначала договор)
- docs/api.md: login — ник берётся из Telegram и обновляется при каждом входе; get-hand/start-battle/submit-round — рука ровно 4 карты на слот (между раундами может быть меньше 3-х? нет: меньше 4, если сгорели), у каждой карты новое поле uses_left; новый код ошибки CARD_BURNED; раздел «Принятые решения» — правило руки и лимита карт.
- AGENTS.md, раздел «Принятые числа»: «Рука: 4 карточки на слот. Лимит карты — 3 боя, затем сгорает».

Шаг 2. База данных
- Новая миграция supabase/migrations/20261025_card_limits.sql:
  - player_cards: колонка uses_left int not null default 3.
  - make_battle_hand(player, battle_id, require_full): пул только uses_left > 0; исключает карты, использованные в этом баттле (с фолбэком на полный пул); limit 4; на старте баттла требует 4 (иначе CARD_POOL_TOO_SMALL), при передаче между раундами берёт сколько есть (≥3 — софт-лок в середине баттла исключён математически).
  - submit_round_atomic: проверка uses_left > 0 у выбранных карт (иначе CARD_BURNED); списание uses_left только для карт, не использовавшихся в предыдущих раундах этого баттла (до вставки раунда, внутри транзакции — идемпотентные повторы не сжигают дважды).
  - cards_for_hand/hand_json получают player_id и добавляют uses_left (join с player_cards); старые сигнатуры дропаются, гранты service_role переоформляются.
- backend/schema.sql: колонка uses_left в player_cards (для чистых установок).
