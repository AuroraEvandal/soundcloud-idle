# Проект: симулятор рэпера (Telegram Mini App)

Игра, где игрок собирает строчки из карточек, получает оценку ИИ-судьи, побеждает ботов в баттлах и растёт в уровне и популярности. Российская сцена, вымышленные персонажи, мат с цензурой.

## Структура репозитория

- `frontend/` : мини-апп (Vite + React). Работает друг.
- `backend/` : Supabase (SQL-схема, Edge Functions на TypeScript). Работаю я.
- `docs/` : документация.

## Сначала прочитай эти файлы

- `docs/game-design.md` : правила игры.
- `docs/api.md` : договор между фронтом и бэкендом (форматы запросов и ответов, коды ошибок, принятые решения).
- `backend/schema.sql` : структура базы данных.

## Правила работы

1. **Работай только в своей папке** (`frontend` или `backend`), если тебя явно не попросили иначе.
2. **Не меняй формат API молча.** Если нужно изменить запрос или ответ, сначала правится `docs/api.md`, и об этом говорится людям.
3. **Фронт присылает только ID** (карточек, батла, соперника). Тексты, оценки, очки, опыт всегда считает сервер.
4. **Игровую логику не держи в браузере.** На клиенте только интерфейс и временное состояние экрана. Все обращения к серверу идут через один файл `frontend/src/api.js`.
5. **Секреты:** токены и ключи только в `.env` (локально) и Supabase Secrets (на сервере). Никогда не коммить их и не вписывать в код. Ключ `service_role` используется только в серверных функциях, во фронте допустим только `anon`.
6. **Оценка раунда:** рифму и флоу считает код, ИИ оценивает только панч и смысл и возвращает строго JSON.
7. **Маленькие шаги.** Делай небольшие изменения, после каждого рабочего предлагай сделать commit.
8. **Люди в проекте новички.** Объясняй простыми словами, что именно ты изменил и как это проверить.

## Принятые числа

- Опыт до следующего уровня: `round(100 * 1.1^(level - 1))`.
- Победа в батле: +25 опыта, +15 популярности.
- Поражение: -10..15 опыта, -5..10 популярности (ниже 0 и ниже порога открытой локации не падает, уровень не понижается).
- Рука: 4-6 карточек на каждый из 4 слотов (setup, development, boost, punch).
